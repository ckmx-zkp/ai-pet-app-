# 07 — 技术选型分析与决策

> 2026-07 基于 `D:\Home_Work` 五仓现状的整体分析结论。决策前提：**前期无开发人员，采用 AI 驱动开发（vibe coding）**。

## 1. 五仓技术栈现状

| 仓库 | 状态 | 技术栈 |
|------|------|--------|
| `ESP32_XIAOZHI` | 已锁定（已有工程） | ESP32-P4 + ESP-IDF 5.4+ + C++，CMake/idf.py 构建，LVGL UI，Opus 音频，MCP 设备控制 |
| `xiaozhi-server` | 已锁定（零代码，方向已定） | fork `xinnan-tech/xiaozhi-esp32-server`：Python 主服务 + Java/Vue 智控台 + MySQL + Redis；ASR/LLM/TTS 全走外部 API；Docker Compose |

## 2. 决策约束

1. **无开发人员，vibe coding**：选型核心标准从"团队熟悉度"变为"AI 生成质量 + 试错循环长度"。Web/Python 语料最丰富，浏览器是最透明的验证环境（写完刷新即见、报错原文可回喂 AI）。
2. **V0.2 功能无原生能力刚需**：登录/绑设备/人设/记忆/历史全部为 REST + JWT 的 CRUD 页面。
3. **多平台一套代码**：iOS / Android / Windows / macOS，不愿维护多套。
4. **内测阶段**：分发求快求简，样机并发 1~2，性能不是瓶颈。

## 3. 关键决策点与对比

### 3.1 后端语言（ai-pet-backend，当前唯一阻塞项）

| 候选 | 结论 |
|------|------|
| **Python 3.12 + FastAPI（选定建议）** | 与 xiaozhi-server 主服务同语言；persona 编译、记忆候选、日运摘要等 LLM 任务全在 Python 生态；FastAPI 自带 OpenAPI/Pydantic 校验，AI 生成后可自验证；Alembic 迁移（docs/02 已点名） |
| Node + NestJS | 与语音侧 Python 生态割裂，LLM 工具链弱 |
| Java / Go | 样机阶段过重 / LLM 编排生态弱，均不推荐 |

### 3.2 管理台框架（ai-pet-admin）

- **建议 Vue 3 + Vite + Element Plus**：xiaozhi-server 自带智控台 manager-web 为 Vue，二开时保持同一前端心智；Vite 已被约定锁定。
- admin 与本仓**平级**（都是 backend 的消费者），不构成相互阻塞。

### 3.3 用户端形态（本仓）：PWA vs Flutter vs 原生

| 维度 | **PWA（选定）** | Flutter | 原生双端 |
|------|----------------|---------|----------|
| AI 生成质量 | 高（Web 语料最大） | 中（语料少、流派多） | 低且双份 |
| 试错循环 | 刷新即见 | 编译 + 热重载摩擦 | 最慢 |
| 平台覆盖 | 浏览器即四端，响应式断点=CSS 媒体查询 | 一套代码四端 | 两套起 |
| 分发 | URL 即达，零成本 | 各端打包/审核 | 各端打包/审核 |
| 短板 | iOS 推送受限、无托盘、Token 存浏览器 | 生态割裂于其他仓 | 人力翻倍 |

**PWA 的短板恰好全部落在 V0.2 之外**（推送=Could 后置、托盘=V1.0、配网本就只需图文引导），故对本项目为最优解。

### 3.4 演进路径（退可守、进可攻）

```
第一阶段：纯 Vue SPA（业务页面）
第二阶段：vite-plugin-pwa → 可安装到主屏/桌面、离线缓存
第三阶段：需要推送/上架 → Capacitor 包原生壳，业务代码零重写
```

## 4. 最终技术栈全景

```text
硬件    ESP32-P4 · ESP-IDF 5.4+ · C++ · LVGL · Opus · MCP
          │ WebSocket / MQTT+UDP（OTA 走 HTTPS）
语音面   xiaozhi-esp32-server（Python 主服务 + Java/Vue 智控台）
          │ 外部 ASR/LLM/TTS API · 内网 HTTP 旁路
业务面   ai-pet-backend：Python 3.12 + FastAPI + SQLAlchemy + Alembic
          │ PostgreSQL 16(+pgvector) · Redis 7 · JWT · REST /api
          ├─ ai-pet-admin：Vue 3 + Vite + Element Plus（Web SPA）
          └─ ai-pet-app（本仓）：Vue 3 + Vite + TS + PWA
部署    Docker Compose · 单机 4C16G · Nginx/Caddy 反代 · 无 GPU
```

## 5. 落地顺序

1. **先拍板并实施 backend**（FastAPI 骨架 → 按 `ai-pet-backend/docs/06` 逐个端点实现，每个带 pytest）——它是唯一阻塞项；
2. 本仓先行部分仅限 Epic A 工程壳 + 假数据摆页面，网络层等后端 API 真实契约落地后再对齐；
3. admin 并行可做，与本仓同栈复用 API 客户端层与组件约定；
4. 每完成一块即联调验证，不攒批次。
